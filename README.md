# Taiga Web

Веб-панель оператора для клиента [Taiga](../taiga): подписки, документы на Яндекс Диске и мастер
«Своя нода». Один вход по паролю, все данные на сервере панели.

## Что умеет

- **Подписки.** Каждая подписка отдаётся по секретному адресу `/sub/<токен>` в формате клиента:
  шапка `name / telegram / site / message`, затем ссылки `taiga://` выбранных нод. Клиент Taiga
  добавляет её как подписку по адресу и обновляет при каждом запуске. Адрес можно сменить, если
  он утёк: старый сразу перестаёт работать. Видно, когда подписку читали в последний раз.
- **Синхронизация с Remnawave.** Подписка на каждого пользователя Remnawave раз в 5 минут: новые
  получают, удалённые теряют, не ACTIVE получают отказ (403). Адрес: `/sub/<shortUuid>`, тот же
  shortUuid, что в ссылке Remnawave, поэтому его можно поставить кнопкой на страницу подписки
  Remnawave; перевыпуск подписки в Remnawave меняет и его. Название, сообщение и ноды задаёт шаблон.
- **История.** Каждое чтение клиентом (время, IP, User-Agent) хранится 30 дней, счётчики по дням
  (чтения и разные IP, UTC) хранятся год. В списке подписок: поиск по имени, пользователю,
  Telegram ID и почте, фильтры, постраничный вывод.
- **Документы Яндекс Диска.** Панель кладёт пустой `.docx` в папку на Диске владельца и больше
  ничего с ним не делает. Доступ по ссылке на редактирование включите в интерфейсе Диска и
  вставьте адрес редактора `https://docs.yandex.ru/edit/d/…` в панель. Затем ядро проверяет
  документ так, как его увидит нода: анонимно и на редактирование.
- **Мастер «Своя нода».** Тот же мастер, что в клиенте, через ядро `--node-wizard`: SSH паролем
  или ключом с подтверждением отпечатка, транспорты (документ Яндекса, который можно создать
  прямо в мастере; Mail.ru; cups.online; Direct в резерве), план изменений на сервере, установка,
  проверка. Проверку делает ядро на сервере панели: оно поднимается клиентом на свободных портах,
  и запрос на `api.ipify.org` должен выйти с адреса VDS. Пароли и вставленный ключ живут только в
  памяти, пока открыт мастер; постоянный ключ можно сохранить в настройках.
- **Remnawave и SSH-ключ** (Настройки → Расширенные). По адресу панели Remnawave и её API-токену
  панель читает список нод (`GET /api/nodes`) с флагами стран и отмечает, где уже стоит Taiga;
  мастер предлагает их адреса. Сохранённый SSH-ключ мастер берёт сам, вставлять его каждый раз не
  нужно. Токен, ключ и его пароль лежат только в `data/db.json` (0600) и в браузер не отдаются.
- **Ноды.** Ноды из мастера и добавленные по ссылкам `taiga://`. Здесь же
  переименование (новое имя попадает в ссылку) и копирование ссылки.
- **Журнал** действий панели, без ключей и паролей.
- **Флаги эмодзи** рисует шрифт Twemoji Country Flags (`/sub/_/flags.woff2`): в Windows своих флагов
  нет, и вместо 🇩🇪 видно «DE». Шрифт покрывает только флаги, остальной текст не меняется.
- **Остальные эмодзи** (⭐ и другие в именах нод) берутся из системного шрифта эмодзи. Где его нет
  (Linux без пакета эмодзи), браузер скачивает нужные части Noto Color Emoji (COLRv1, OFL) из
  `assets/fonts/noto-color-emoji` через `/sub/_/emoji.css`, только те диапазоны, что есть на странице.

## Запуск

Нужны Node.js 22 и Linux-сборка ядра Taiga (`npm run core` в `~/taiga`). По умолчанию берётся
`~/taiga/resources/linux/taiga-core-linux-amd64`.

```bash
cp .env.example .env      # задайте ADMIN_PASSWORD, DATA_KEY и PUBLIC_URL
npm install
npm run build
npm start                 # http://127.0.0.1:8787
```

Разработка: `npm run dev` поднимает API на 8787 и Vite на 5173 с прокси.

Клиенты читают подписку по адресу панели, поэтому `/sub/` нужно открыть наружу через https:
nginx или Caddy перед панелью, `PUBLIC_URL=https://…` и `TRUST_PROXY=1`. Остальное (`/api`, сами
страницы) можно держать за VPN или ограничить по адресам.

### nginx и HTTPS (Docker)

`compose.yaml` поднимает панель за nginx (порты 80 и 443) и certbot, который продлевает сертификат
Let's Encrypt. Сама панель слушает 8787 только на `127.0.0.1` сервера. Домен должен указывать на сервер.

1. В `.env` задайте `DOMAIN=panel.example.com` и `PUBLIC_URL=https://panel.example.com`.
2. `docker compose up -d --build`: пока сертификата нет, nginx отдаёт панель по http.
3. Выпустите сертификат и перезапустите nginx, чтобы он перешёл на https:

   ```bash
   docker compose run --rm --entrypoint certbot certbot certonly --webroot -w /var/www/certbot \
     -d panel.example.com --email you@example.com --agree-tos -n
   docker compose restart nginx
   ```

Дальше certbot проверяет продление дважды в день, а nginx перечитывает сертификат раз в 6 часов.
Сертификаты лежат в `nginx/letsencrypt`: переносите эту папку вместе с `data/`.

### Настройки из .env

Любую настройку со страницы «Настройки» и шаблона синхронизации можно задать в `.env`: `YANDEX_TOKEN`,
`YANDEX_DOCS_FOLDER`, `REMNAWAVE_URL`, `REMNAWAVE_TOKEN`, `SSH_PRIVATE_KEY` (или `SSH_PRIVATE_KEY_FILE`),
`SSH_PASSPHRASE`, `SSH_USER`, `REMNAWAVE_SYNC`, `SYNC_NAME`, `SYNC_TELEGRAM`, `SYNC_SITE`,
`SYNC_MESSAGE`, `SYNC_NODES` (описание в `.env.example`). Такая переменная важнее сохранённого
значения: поле на странице блокируется, а значение не пишется в `data/db.json`. Если убрать переменную,
вернётся сохранённое. Пустая переменная не считается. Неверное значение не даёт панели запуститься
и называет переменную. Изменения вступают в силу после перезапуска.

### Шифрование данных

Токены Яндекса и Remnawave, SSH-ключ с паролем, ссылки нод (в них ключи каналов) и секреты адресов
подписок (в `panel.sqlite`, поиск по HMAC) лежат зашифрованными AES-256-GCM ключом `DATA_KEY` из `.env`
(`openssl rand -base64 32`). Копия `data/` без `.env` бесполезна, поэтому храните их раздельно.
Если потерять `DATA_KEY`, сохранённые секреты не восстановить: ноды придётся добавить заново, а
токены и ключ ввести снова. База без шифрования шифруется при первом запуске. Панель держит
секреты открытыми в памяти, так что от взлома самого сервера шифрование не защищает.

### Токен Яндекс Диска

1. Создайте приложение на <https://oauth.yandex.ru/client/new> с доступами «Чтение всего Диска» и
   «Запись в любом месте на Диске».
2. Под владельцем Диска откройте
   `https://oauth.yandex.ru/authorize?response_type=token&client_id=<ClientID>` и вставьте токен в
   «Настройках» панели.

Право «редактирование по ссылке» Яндекс открывает не на всех аккаунтах (в веб-интерфейсе это
настройка тарифов Яндекс 360).

## Как устроено

```
server/
  index.ts          Fastify: вход, API, /sub/<токен>, раздача собранных страниц
  subpage.ts        страница подписки для браузера: тот же /sub/<токен>, QR-код адреса
  remnawave.ts      ноды и пользователи панели Remnawave по API-токену
  sshkey.ts         тип и отпечаток SHA256 сохранённого SSH-ключа
  secrets.ts        AES-256-GCM для секретов в db.json ключом DATA_KEY
  overrides.ts      настройки из .env поверх сохранённых
  db.ts             data/db.json (0600): настройки, ноды со ссылками и ключами, документы
  store.ts          data/panel.sqlite (0600, WAL): подписки, чтения за 30 дней, счётчики по дням,
                    сессии входа (хэш токена, привязан к ADMIN_PASSWORD; 30 дней, продлеваются)
  sync.ts           синхронизация с Remnawave раз в 5 минут, чистка истории раз в час
  core.ts           ядро: --parse-link / --make-link
  verify.ts         проверка через ноду: ядро клиентом + запрос через его HTTP-прокси
  yandex.ts         REST API Диска: папка, загрузка, удаление, адрес редактора опубликованного файла
  docx.ts           пустой .docx без зависимостей
  wizard/service.ts ядро --node-wizard (перенесён из клиента)
  wizard/session.ts шаги мастера на сервере; страница только показывает состояние
  core/config.ts, core/ipc.ts  перенесены из клиента без изменений
shared/
  model.ts          модель клиента Taiga (копия ~/taiga/shared/model.ts)
  panel.ts          типы панели
web/src/            React + Tailwind v4, тёмная тема в стиле киберпанк
```

`shared/model.ts`, `server/core/*.ts` и `server/wizard/service.ts` скопированы из клиента: при
изменении формата ссылок или протокола мастера в Taiga их нужно обновить.
